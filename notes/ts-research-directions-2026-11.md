## 0. 结论先行（v3：只做改进）

### 0.1 推荐的改进方案（按优先级）

**改进 A ★★★（首推，已本地验证）：SCM（Static-Calendar Mixing，静态-日历跨变量混合）**

用它替换 iTransformer 类模型中“每个样本重新计算”的注意力式通道混合，由三部分组成：

- 一个学到的**静态**混合矩阵：低秩 + 稀疏结构，零初始化，训练时加 DropConnect；
- **日历时间嵌入**（小时 + 星期几，零初始化）；
- **随时段变化的低秩修正**。

本地结果（同一骨干、同一训练预算），相对“注意力 + 时间信息”（iTransformer 的公平类比）的 MSE 下降：

| 数据集 | 误差下降 |
|---|---|
| PEMS04 | −46% |
| PEMS08 | −26% |
| ECL | −14% |
| Traffic | −9% |
| Weather | −9% |
| ETTm1 | −3% |
| ETTh1 | 持平 |
| Solar | +2%（略差） |

8 个数据集中赢 7 个；单次训练耗时缩短 27–40%。

**改进 B ★★（次推，已本地验证）：给“先粗后细”的预测模型加按样本自适应的提前停止**

适用于 SCALER 这类模型。在误差不超过“最佳固定步数 +1%”的前提下省 7–32% 的计算；在中等算力预算下，精度最多高 10%。

**改进 C ★（探索，尚未验证）：原生多变量时序基础模型的分组策略**

Chronos-2 的多变量模式已比逐通道零样本好 9–15%。下一步要回答：怎样给变量分组，能把这部分收益再往上推？

**不再推荐**：
- Mamba 扫描顺序；
- LLM 语义先验图；
- 按相位或按样本“换图”；
- 用注意力实现的“动态依赖”模块（已被 SCM 取代）；
- 依赖可用性诊断等分析类工作（按你的要求不做）；
- 以及 v1 中列出的：LLM 当数值预测骨干、单种子刷 SOTA、单纯换 Mamba、单纯做测试时适应（TTA）。

### 0.2 各方向的验证结果与去向

| v1 方向 | 关键实验证据（详见第 5 节） | 结论 | 去向 |
|---|---|---|---|
| ① 按周期相位条件化的依赖**图** | 相位平均相关最接近未来相关（9/9），但当预测图并不比静态图好（PEMS 上差 4–8 个点） | ❌ | 放弃 |
| ①′ 随时段变化的跨变量**交互权重** | 交通数据：线性模型再降 5–10%，神经网络相对“静态 + 时间嵌入”这一公平对照再降 6.5–8.3% | ✅（交通类数据） | 并入改进 A 的“日历修正” |
| ② 因子 + 稀疏（用注意力实现） | 合成数据有效，但真实数据上打不过静态混合 | ❌（原实现） | 放弃 |
| ②′ 静态结构化混合 | 6 个耦合数据集上，静态混合赢 5 个、平 1 个；PEMS 上领先 26–34%；换种子、换学习率后结论不变 | ✅ 证据最强 | 成为改进 A 的核心 |
| ③ Mamba 变量扫描顺序 | 顺序间差异 ≤3%，PEMS08 上小于种子噪声；谱排序无益 | ❌ | 放弃 |
| ④ 自适应测试时计算 | 收益集中在少数样本；省 7–32% 计算 | ✅ 中等 | 改进 B |
| ⑤ 基础模型 + 外挂适配器 | 原生多变量模式 +9–15%，外挂线性适配器无效 | ⚠️ 部分 | 改为改进 C（分组策略） |
| ⑥ LLM 语义先验图 | 数据充足时对预测没有作用 | ❌ | 放弃 |

> **重要前提**：所有实验都在 4 核 CPU、无 GPU 的容器里完成，模型小、训练短，大数据集做了降采样，多数单种子。关键结论另做了多种子复核（5.7 节）。这些结果足够用来决定“往哪里投入”，但写论文前必须在 GPU 上，用完整数据和标准超参，在官方代码框架里复现。

## 3. 横向分析：共同的隐含假设与短板（改进的出发点）

### 3.1 “动态/稀疏依赖”大多名不副实

下表按各论文自己的公式和描述，逐篇拆解它们宣称的机制实际是什么。

| 论文 | 宣称 | 实际机制 | 推理期能否按样本自适应？是否显式稀疏？ |
|---|---|---|---|
| CACRN | 分离无关变量 | 模糊 C 均值在主网络之外单独求解，簇数 k 仍要在验证集上搜索 | 基本是静态的；软隶属，不稀疏 |
| DyTimeNet | 动态稀疏依赖 | DropFusion 只在训练时随机丢边、丢神经元；测试时去掉掩码，按比例缩放 | 通道混合权重在推理期固定，只靠激活函数带来很弱的输入依赖；推理期不稀疏 |
| MPGTimer | 图增强的动态依赖 | 图项 G_ij = (HW_g)_i · (HW_g)_j，和 QKᵀ 一样是双线性相似度。两者相加等于给注意力打分加一个对称的低秩项，并没有引入显式的变量级图；结构掩码 A 默认全连接 | 自适应程度和普通注意力相同；不稀疏，复杂度 O((C·N)²) |
| MoVE | 稳健的跨变量注意力 + 动态门控 | RCVA = Softmax(GELU(A − LSE(A)))，见下方推导 | 注意力接近均匀，约等于跨通道取平均；门控值也接近均匀 |
| GPS-Mamba | 动态扫描顺序 | 动态顺序来自预先构建的有限仓库（默认 50 个排列），用冻结的 S-Mamba 嵌入做最近邻检索；仓库里的排列由训练样本**未来窗口**的相关性算出 | 只能在有限候选中离散挑选，不可微；训练期存在轻微“看未来”，训练和测试不一致（作者自己承认） |

**MoVE 的 RCVA 推导（我的判断）**

这是按论文式 (3) 推出来的。如果官方代码和公式不一致，以代码为准。

- A − LSE(A) 就是 log-softmax，取值都 ≤ 0。
- GELU 在 (−∞, 0] 上的取值只落在 [−0.17, 0] 之间。
- 再过一次 softmax，任意两个变量的权重之比都不超过 e^0.17 ≈ 1.19。
- 变量一多（例如 ECL 有 321 个），log-softmax 大多在 −log C ≈ −5.8 附近，GELU 输出几乎都是 0，注意力基本就是**均匀平均**。
- 这个映射还是**非单调**的：最相关和最不相关的变量都会拿到接近最大的权重。

所以它“防止注意力塌缩”的方式，其实是取消了选择性。另外，论文附录 Table 6 中的门控值：周期输入下 Expert1 = 0.320，其余专家在 0.205–0.241 之间，整体接近均匀。这和正文所说的“0.68 / 0.72”对不上。

> **对改进的启示**：先导实验（5.1、5.2）表明，“动态”依赖在这些基准上的实际收益很有限，一张学到的静态混合矩阵反而更好。这正是改进 A（SCM）的出发点：**与其把“动态”做得更复杂，不如把“静态结构 + 日历信息”做好。**

### 3.2 各模型都需要逐数据集调“用多少跨变量信息”

几篇论文的观察：

- **MPGTimer**：在 ECL 上输给 Timer-XL。作者的解释是，ECL 的变量相关主要来自“时间对齐的公共周期”，而不是结构性的交互。
- **GPS-Mamba**：在 Weather、ECL 上增益很小，在 SD、PEMS 上增益很大。
- **DyTimeNet 的消融**：Weather 更依赖跨变量模块，ETT/ECL/Traffic/ILI 更依赖时间模块。而且把跨变量模块换成自注意力，比直接删掉还差。
- **MoVE 的消融**：在 Solar 和 ETTm2 上，同时去掉 RCVA 和门控，结果在部分指标上反而更好。

每个模型都靠一个“旋钮”控制要用多少跨变量信息，而且都只能逐个数据集调：

| 模型 | 旋钮 |
|---|---|
| CACRN | 簇数 k |
| DyTimeNet | 丢弃率 p1/p2，最优值从 0.3 到 0.8 不等 |
| GPS-Mamba | 稀疏阈值 ε 和仓库大小 n_s，n_s 最优值从 25 到 200 不等 |
| MoVE | 门控 |

> **对改进的启示**：SCM 用三个设计，让跨变量模块“有用就用、没用就不伤害”，不必逐数据集手调：
> - 零初始化：训练起点等价于 CI 模型；
> - DropConnect：抑制过拟合；
> - 低秩 + 稀疏的 W：参数量随变量数线性增长，而不是平方增长。

### 3.3 稠密注意力不是跨变量混合的好归纳偏置

多篇论文互相印证：

- S-Mamba：在变量维上，Mamba 优于注意力。
- DyTimeNet：把跨变量模块换成注意力，比删掉它还差。
- MoVE：原始注意力会塌缩，而它的“修复”实际上是近乎均匀的混合。
- Tan et al.：一层注意力加上 patch 就能追平 LLM。

v2、v3 的实验直接验证了这一点（5.2、5.7 节）。

### 3.4 评测协议薄弱，基准趋于饱和

- **基线数字多是照抄的。** MoVE 抄 TQNet，SCALER 抄 LVICL，MPGTimer 的主表抄 Timer-XL 和原论文。lookback、超参、随机种子都不统一。MoVE 只用了一个种子（2024）。所有论文都没有做显著性检验。
- **lookback 设定不一。** MoVE、DyTimeNet、GPS-Mamba、S-Mamba 用 L=96；SCALER、MPGTimer 用 L=672。
- **改进幅度很小。** 在 ETT/Weather/ECL 上的提升常在 0.001–0.01 量级，可能还在种子方差之内。
- **时间信息常被忽略**：仅给 CI 模型加时间嵌入，交通数据误差就降 36–40%（5.7 节）。论文里的跨变量模块如果和不带时间信息的 CI 基线比，会高估自身作用。
- **训练数据量会反转结论**：ECL、Traffic 降采样后，所有跨变量变体都输给 CI。

### 3.5 任务设定单一

全部论文都是规则采样、无缺失、点预测（只报 MSE/MAE）、不带外部文本。只有 S-Mamba 和 GPS-Mamba 测过“未见变量”的泛化。

### 3.6 LLM 线的核心矛盾仍未解决

- Tan et al. 证明：在这类数值预测里，LLM 可以删掉或随机初始化，效果不变。
- SCALER 显示 LLM 越大效果越好，但**没有做“同结构随机初始化”或“去掉 LLM”的对照**。

**我的判断**：SCALER 的增益可能主要来自“粗到细多尺度监督”这个结构本身，而不是 LLM 的预训练知识。改进 B 正是基于这一点，在不依赖大 LLM 的前提下，让粗到细结构更省算力。

| SOFTS（NeurIPS 2024） | STAR 中心化核心 |
| STID（CIKM 2022） | 空间身份嵌入 + time-of-day / day-of-week 嵌入，交通预测的强基线 |
| TQNet（ICML 2025） | 周期 query 注意力 |
| CycleNet（NeurIPS 2024） | 可学习的周期向量 |

SCM 与它们的区别，需要用消融证明，主要在三点：

1. 静态混合矩阵是低秩 + 稀疏的结构化矩阵，并且配零初始化和 DropConnect；
2. 混合矩阵本身随日历时段做低秩调整，而不只是把时间嵌入加到 token 上；
3. 作为即插即用模块，替换 iTransformer、S-Mamba、TQNet 等模型里的动态混合。

## 5. 先导实验与改进实验

### 5.0 实验条件与局限（请先读）

- **环境**：4 核 CPU、15GB 内存、无 GPU 的云端容器（没有连接你的本地机器）；PyTorch 2.15 CPU 版。
- **数据**：12 个公开数据集。
  - 标准长期预测基准：ETTh1/ETTh2/ETTm1/ETTm2、Weather（Jena 2020，21 变量）、ECL（321）、Traffic（862）、Solar（137）、Exchange（8）。
  - 带路网的交通数据：PEMS04（307）、PEMS08（170），附路网距离。
  - 带语义变量名的数据：AirQuality（12）。
  - 切分：ETT 按 12/4/4 个月，PEMS 按 6:2:2，其余 7:1:2。
  - 用训练集统计量做标准化，误差都在标准化尺度上计算（MSE/MAE）。
- **规模**：
  - 模型都很小：岭回归、2 层 D=64 的小网络、纯 PyTorch 实现的 Mamba。
  - 训练很短：最多 8 个 epoch，带早停。
  - 大数据集做了训练窗口降采样：Traffic 只用约 1/8 的窗口（5.7 节），属于数据偏少的设定。
  - 大多只跑了一个随机种子；关键结论另做了多种子复核。
  - **因此结论只能用来判断“这个方向值不值得投入”，不是论文级结论；绝对数值也不能和论文报告值直接比。**
- **可复现**：每个实验一个脚本，原始结果在 `results/*.json`，汇总表在 `results/SUMMARY.md`。
  - 先导实验：`pilot1_phase.py`、`pilot1b_phase_weights.py`、`pilot1c_phase_mixing.py`、`pilot2_synth.py`、`pilot2_real.py`、`pilot3_order.py`、`pilot4_adaptive.py`、`pilot5_tsfm.py`、`pilot6_prior.py`。
  - 改进实验：`improve_scm.py`。

### 5.1 方向①：按周期相位条件化的跨变量依赖

**做法**

- 数据：9 个数据集，用较短的预测长度，让“一天中的时段”有意义（小时级 L=96、H=12；10 分钟级 L=144、H=36；5 分钟级的 PEMS L=96、H=48）。
- **预测检验**：用岭回归“图-线性”模型 y_c ~ [x_c, (A x)_c]，参数在所有通道间共享。A 依次取以下候选矩阵的 top-k 图：
  - 回看窗口相关；
  - 全局静态相关；
  - 同一相位（预测起点的小时 × 是否周末）的历史平均相关；
  - oracle：直接用预测窗口的真实相关建图。它用到了未来信息，只作为乐观上界。
- **追加实验 1b**：图固定为静态图，只让权重按时段分组；对照组只让“自身历史”的权重随时段变化。
- **追加实验 1c**：用神经网络复核 1b。

**结果**

| 数据集 | 静态图 | 相位图 | 回看图 | oracle（未来相关） | 1b：邻居权重随时段变化的额外收益 |
|---|---|---|---|---|---|
| PEMS08 | +14.4% | +10.2% | +9.8% | +10.2% | **+9.9%** |
| PEMS04 | +17.1% | +9.1% | +9.5% | +11.4% | **+5.2%** |
| Traffic | +2.5% | +3.2% | +4.7% | **+12.7%** | **+5.7%** |
| ECL | +4.2% | +4.1% | +3.0% | **+16.1%** | −3.7% |
| Solar | +6.8% | +5.7% | +7.4% | +7.6% | +0.0% |
| Weather | +2.8% | +3.2% | +1.4% | +6.7% | +0.9% |
| ETTh1 / ETTm1 / AirQuality | −1.1% 到 +1.0% | −0.7% 到 +1.2% | −0.5% 到 +0.4% | −0.9% 到 +2.7% | ETTm1：−2.1% |

表中前四列是相对 CI 的误差下降；最后一列是“自身和邻居权重都随时段变化”相对“只有自身权重随时段变化”的误差下降。

| 1c（H=48） | CI + 时段嵌入 | 静态稠密 | 静态稠密 + 时段嵌入 | **时段条件化混合 + 时段嵌入** | 相对公平对照 |
|---|---|---|---|---|---|
| PEMS08 | 0.264 | 0.234 | 0.208 | **0.190** | **−8.3%** |
| PEMS04 | 0.293 | 0.178 | 0.173 | **0.162** | **−6.5%** |

**结论**

- 按相位换一张图，预测并不会更好：在高维数据上，短窗口里的 top-k 邻居几乎无法预测（Jaccard 只有 0.07–0.27），长期静态图更稳。
- 但“让变量间的混合方式随时段变化”在交通数据上稳定有效：线性模型和神经网络都支持，相对含时间嵌入的公平对照再降 6–10%。
- 这一结论**并入改进 A 的“日历修正”**。

### 5.2 方向②：因子 + 稀疏 → 静态结构化混合

**(A) 合成数据：真实结构已知**

- 数据构造：40 个变量，每个变量 = 2 个公共因子（日周期 + 慢趋势）+ 稀疏的滞后 VAR 残差。另设一种“依赖图按昼夜切换”的版本。每种设定跑 3 个种子。

| 建图方式 | 恢复真实结构的 AUROC（静态 / 切换） |
|---|---|
| **原始相关**（CACRN、GPS-Mamba 等论文的建图方式） | **0.52 / 0.49（约等于随机）** |
| 去掉公共因子后再算相关 | 0.76 / 0.71 |
| 去因子后的滞后相关 | 0.94 / 0.91 |
| 去因子后做 VAR 回归 | 1.00 / 0.99 |

- 有公共因子时，相关性建图基本失效；建图前要先去掉因子。SCM-LRS 的稀疏结构就是在去因子后的相关上取 top-k。
- 即使真实图在切换，分时段估计的图也不比静态图更好（+10.5% vs +10.4%）。

**(B) 真实数据：同一骨干，只换跨变量混合模块（不含时间信息）**

| 数据集 | C | CI | 注意力 | 因子 + 稀疏（注意力实现） | **静态稠密** | **静态低秩 + 稀疏** |
|---|---|---|---|---|---|---|
| Weather | 21 | 0.238 | 0.231 | 0.226 | 0.206 | **0.206** |
| Solar | 137 | 0.280 | 0.265 | **0.260** | 0.261 | 0.269 |
| PEMS08 | 170 | 0.797 | 0.572 | 0.568 | **0.420** | 0.422 |
| PEMS04 | 307 | 0.859 | 0.572 | 0.586 | **0.375** | 0.442 |
| ECL（训练窗口 ÷3） | 321 | 0.198 | 0.193 | 0.191 | 0.179 | **0.169** |
| ETTm1 | 7 | 0.323 | 0.335 | 0.338 | 0.320 | **0.317** |
| ETTh1 / ETTh2 / ETTm2 / Exchange / AirQuality | 7–12 | **CI 最好** | 差 0.5–6.2% | 差 3.0–5.6% | 差 0.3–12% | 差 0.1–11% |
| 欠训练：ECL（÷12）/ Traffic（÷24） | 321 / 862 | **CI 最好** | 差 11–15% | **伤害最小**（差 2.6–4.2%） | **伤害最大**（差 18–22%） | 差 10–11% |

- 换随机种子后结论不变；给注意力调低学习率反而更差。

**结论**

- 随输入变化的混合（注意力、因子 + 稀疏注意力）没有一次赢过静态混合。
- 静态稠密矩阵的弱点是 O(C²) 参数：数据少时过拟合最严重；低秩 + 稀疏能缓解。
- 这一结论成为**改进 A 的核心**。

### 5.3 方向③：Mamba 在变量维度上的扫描顺序

**做法**：S-Mamba 式结构，同一模型、同一种子，只改变扫描顺序，比较原始、随机、相关图谱排序、路网谱排序、对抗顺序（刻意把相似变量排远）。

| 数据集 | 双向 Mamba：不同顺序的 MSE 范围 | 种子噪声 | 谱排序是否最好？ |
|---|---|---|---|
| Weather（21 个变量，2 层） | 0.2273–0.2343（差 3.1%） | 0.4% | 否（原始顺序最好；它本身就按物理类别分组） |
| PEMS08（170，1 层） | 0.3877–0.3920（差 1.1%） | **1.7%** | 否（对抗顺序反而最好） |
| ECL（321，1 层） | 0.2721–0.2745（差 0.9%） | 未测 | 否（对抗顺序反而最好） |

**结论**：顺序影响很小，谱排序（Laplace 扫描）在 3 个数据集上都没有带来收益。**放弃。**

### 5.4 方向④：自适应测试时计算（先粗后细）→ 改进 B

**做法**

- 模型：不用 LLM 的迷你版 SCALER。第 1 步预测 H/8 分辨率的粗形状，第 2–4 步依次在 H/4、H/2、H 分辨率上细化残差；L=336、H=96。
- 推理时可以在第 k 步停下。
- 停止规则：在验证集上训练一个岭回归，预测“继续细化能带来多少收益”。

**结果**

| 数据集 | k=1 → k=4 的 MSE | 前 20% 样本贡献的细化收益 | 细化后反而变差的样本比例 | 同等算力下比固定步数前沿最多好 | 达到“最佳固定 MSE +1%”所需算力：学习式停止 / 固定步数 |
|---|---|---|---|---|---|
| ETTh1 | 0.547 → 0.412（k=3 已等于 k=4） | 84% | 25% | +8.8% | 0.67 / 0.72 |
| ETTm1 | 0.319 → 0.308 | 86% | 41% | +1.3% | 0.48 / 0.53 |
| Weather | 0.222 → 0.217 | 88% | 41% | +0.4% | 0.54 / 0.72 |
| PEMS08 | 0.370 → 0.351 | 71% | 36% | +3.1% | **0.49 / 0.72** |
| ECL | 0.503 → 0.178 | 39% | 3% | +10.0% | 1.00 / 1.00 |

**结论：可作为效率改进。**

- 在误差不超过“最佳固定 +1%”的前提下省 7–32% 的计算；在中等预算下，精度最多高 10%。
- ECL 是边界条件：细化对几乎所有样本都有益，高精度区间省不下算力。
- “LLM 先验是否必要”的对照需要 GPU，本机没有做。

### 5.5 方向⑤：时序基础模型上的跨变量信息 → 改进 C

**做法**：Chronos-2（1.2 亿参数）零样本预测，上下文 512、H=48。比较单变量模式（逐通道）与原生多变量模式（group attention），并在两者之上各接一个岭回归适配器（CI 版和静态图版），适配器在 24–60 个训练窗口上拟合。

**结果**（相对单变量零样本的误差下降）

| 数据集 | 多变量零样本 | 单变量 + CI 适配器 | 单变量 + 图适配器 | 多变量 + 图适配器 |
|---|---|---|---|---|
| ETTh1（7 个变量） | **+9.3%** | +1.8% | −2.6% | +0.8% |
| Weather（21） | **+14.6%** | −4.3% | −5.4% | +3.8% |
| PEMS08（170） | **+12.0%** | −3.4% | −0.3% | +3.3% |

**结论**：跨变量信息对基础模型有价值，但要在模型内部以“组”的形式利用；外挂的线性适配器无效。所以改进 C 应聚焦在“怎样分组”。

### 5.6 方向⑥：LLM 语义先验 → 稀疏依赖图

**做法**：先验图写于 2026-11-19 16:56，早于任何数据分析（Weather 有 32 条边，AirQuality 有 20 条边）。用岭回归图-线性模型比较四种边集（边权一律取训练集相关）：先验图、数据图、两者并集、随机图。分全量数据和只用 5% 数据两种设定。

| 数据集 | 设定 | 先验图 | 数据图 | 随机图 |
|---|---|---|---|---|
| Weather (H=96) | 全量 | +0.14% | −0.03% | +0.39% |
| Weather | 5% 数据 | −0.65% | −1.48% | −2.33% |
| AirQuality (H=24) | 全量 | −0.60% | −0.80% | −0.33% |
| AirQuality | 5% 数据 | **−7.2%** | −8.4% | −14.5% |

**结论**：数据充足时，任何图对预测的作用都在噪声范围内；少数据时先验图伤害最小，但仍不如不用图。**放弃。**

### 5.7 改进实验：静态-日历跨变量混合（SCM）

**模块定义**（作用在变量 token 表示 h ∈ R^{C×D} 上，替换原来的 Attention(h, h, h)）

```
h ← h + Dropout( (W + A_g B_gᵀ) · V(h) )
  W        ∈ R^{C×C}  静态混合矩阵；默认用低秩 + 稀疏结构：W = U Vᵀ（秩 16）+ S（每个变量 10 个邻居，
                       邻居取去掉公共因子后的训练集相关的 top-k）；零初始化；训练时 DropConnect(0.3)
  A_g, B_g ∈ R^{C×8}  第 g 个日历组的低秩修正（g = 6 个四小时段 × 工作日/周末，共 12 组）；A 零初始化
  V        ∈ R^{D×D}  线性变换
token 表示 += E_hour(预测起点的小时) + E_dow(星期几)      # 日历嵌入，零初始化
```

**实验设置**

- 骨干与 5.2 相同：RevIN → 每个变量 Linear(L→D) → 2 × [混合模块 + FFN] → 输出头；D=64，L=96、H=96，最多 8 个 epoch，带早停。所有变体共用同一骨干、同一训练预算，只换跨变量模块和是否加时间信息。
- 种子 0，多种子复核见下文。
- 对比的变体：

| 变体 | 说明 |
|---|---|
| CI / CI + 时间 | 不做跨变量混合；后者加日历嵌入 |
| 注意力 / 注意力 + 时间 | iTransformer 式；后者是公平类比，因为 iTransformer 本身也使用时间特征 |
| 静态稠密 + 时间 | 一个与输入无关的 C×C 矩阵 |
| SCM（稠密 W） | 静态稠密 + 日历修正，分加不加 DropConnect 两个版本 |
| **SCM-LRS（默认）** | W 取低秩 + 稀疏，加日历修正和 DropConnect |
| SCM-H（混合版） | SCM（稠密 W）+ 并行注意力分支 |

**主结果**（测试集 MSE；最后一列是 SCM-LRS 相对“注意力 + 时间”的变化）

| 数据集 | C | CI + 时间 | 注意力 + 时间 | 静态稠密 + 时间 | SCM（稠密，+Drop） | **SCM-LRS（默认）** | SCM-H（混合） | SCM-LRS 相对注意力 + 时间 |
|---|---|---|---|---|---|---|---|---|
| PEMS04 | 307 | 0.484 | 0.448 | 0.281 | 0.243 | 0.244 | 0.250 | **−45.5%** |
| PEMS08 | 170 | 0.477 | 0.448 | 0.378 | 0.343 | 0.331 | **0.329** | **−26.1%** |
| ECL | 321 | 0.194 | 0.190 | 0.183 | 0.169 | **0.164** | 0.170 | **−13.6%** |
| Weather | 21 | 0.228 | 0.225 | **0.201** | 0.206 | 0.206 | 0.209 | **−8.6%** |
| Traffic（数据偏少） | 862 | **0.895** | 1.122 | 1.184 | 1.224 | 1.021 | 1.254 | **−8.9%** |
| ETTm1 | 7 | 0.320 | 0.326 | 0.315 | **0.314** | 0.316 | 0.321 | −3.2% |
| ETTh1 | 7 | 0.379（CI 不加时间 0.376） | 0.390 | 0.391 | 0.390 | 0.388 | 0.390 | −0.4% |
| Solar | 137 | 0.238 | 0.231 | 0.236 | 0.236 | 0.236 | **0.230** | +2.3% |

**各组件的作用**（逐步添加时 MSE 的变化；负数表示更好）

| 组件 | PEMS04 | PEMS08 | ECL | Weather | Traffic | ETTm1 | Solar |
|---|---|---|---|---|---|---|---|
| 时间嵌入（CI → CI + 时间） | −36% | −40% | −2% | −4% | — | −1% | −13% |
| 静态混合取代注意力（注意力 + 时间 → 静态稠密 + 时间） | −37% | −16% | −4% | −11% | +6% | −3% | +2% |
| 日历修正（静态稠密 + 时间 → SCM） | **−14%** | **−8%** | −1% | +3% | +9% | +2% | 0% |
| DropConnect（SCM → SCM + Drop） | +1% | −2% | **−7%** | −1% | −5% | −2% | 0% |
| 低秩 + 稀疏 W（SCM + Drop → SCM-LRS） | +1% | −3% | −3% | 0% | **−17%** | +1% | 0% |

**效率**（CPU 上单次训练耗时，含早停）

| 数据集 | 注意力 + 时间 | SCM-LRS | 缩短 |
|---|---|---|---|
| PEMS04 | 211s | 126s | 40% |
| PEMS08 | 128s | 82s | 36% |
| ECL | 455s | 289s | 36% |
| Traffic | 523s | 378s | 28% |
| Solar | 230s | 157s | 32% |
| Weather | 63s | 46s | 27% |

- 参数量方面需要注意：日历修正项的参数随变量数线性增长（12 组 × C × 8 × 2，每层），所以在变量很多的数据集上，SCM-LRS 的参数比注意力多（ECL 约 21 万 vs 8 万）。如果需要，可以让各组共享 B_g，或降低秩来压缩。

**多种子复核**（测试集 MSE，均值 ± 标准差；“胜出种子数”是在同一种子下 SCM-LRS 优于“注意力 + 时间”的次数）

| 数据集 | 种子数 | 注意力 + 时间 | 静态稠密 + 时间 | **SCM-LRS** | SCM-LRS 相对注意力 + 时间 | 胜出种子数 |
|---|---|---|---|---|---|---|
| PEMS04 | 3 | 0.448 ± 0.001 | 0.280 ± 0.002 | **0.245 ± 0.002** | **−45.2%** | 3/3 |
| PEMS08 | 3 | 0.448 ± 0.001 | 0.379 ± 0.008 | **0.338 ± 0.009** | **−24.7%** | 3/3 |
| ECL | 2 | 0.190 ± 0.000 | — | **0.165 ± 0.001** | **−13.3%** | 2/2 |
| Weather | 3 | 0.226 ± 0.002 | **0.202 ± 0.000** | 0.207 ± 0.001 | −8.3% | 3/3 |
| ETTm1 | 3 | 0.327 ± 0.003 | **0.315 ± 0.002** | 0.317 ± 0.001 | −3.1% | 3/3 |
| Solar | 3 | **0.230 ± 0.001** | 0.237 ± 0.001 | 0.234 ± 0.003 | +1.9% | 0/3 |

- 换种子后结论完全一致：在 5 个数据集上，SCM-LRS 在每一个种子下都优于“注意力 + 时间”，差距远大于种子波动；Solar 在每个种子下都略差。
- 在 Weather、ETTm1 上，最好的其实是“静态稠密 + 时间”，日历修正和低秩 + 稀疏没有额外帮助。日历修正的作用集中在交通数据上，低秩 + 稀疏的作用集中在变量多的数据集（ECL、Traffic）上。所以论文里可以把“日历修正”和“低秩 + 稀疏”写成按数据特点启用的组件，也可以做自动选择。

**解读**

1. **SCM-LRS 相对 iTransformer 式“注意力 + 时间”，在 8 个数据集中赢 7 个**：PEMS04、PEMS08 上降 26–46%，ECL、Weather、Traffic 上降 9–14%，ETTm1 降 3%，ETTh1 持平。只在 Solar 上差 2.3%。
2. **收益来源因数据而异**：
   - 交通数据：主要来自“静态取代注意力”和“日历修正”；
   - ECL：主要来自 DropConnect 和低秩 + 稀疏；
   - Traffic：主要来自低秩 + 稀疏（控制参数量）；
   - Weather：主要来自静态混合。
   这说明各组件分工明确，可以写出很清楚的消融。
3. **两个短板及对应改法**：
   - **Solar**：变量间关系可能确实是动态的（云层移动）。混合版 SCM-H 在 Solar 上最好（0.230），可以作为“动态依赖强的数据集”的扩展版本。
   - **Traffic 数据偏少时**：带时间的 CI 仍然最好（0.895）。需要在 GPU 上用完整数据确认；如果仍然如此，需要更强的容量控制，例如更低的秩，或者按验证集自动选秩。
4. **最重要的公平性提醒**：时间嵌入本身在交通数据上就能带来 36–40% 的提升，所以 SCM 必须和带时间信息的基线比（本实验已这样做）。否则会把时间信息的功劳算到跨变量模块头上。

## 6. 改进方案（详细）

### 改进 A ★★★：SCM——用“静态结构化混合 + 日历修正”替换动态跨变量模块

**定位**

- 一个即插即用的跨变量模块，替换现有 SOTA 模型里的注意力 / Mamba / 动态图混合。
- 论文故事：“动态依赖并非必要：静态结构化混合 + 日历调制更准、更快”，以“改进方法 + 消融”的形式呈现，而不是分析论文。

**可以直接插入的现有模型**

| 模型 | 替换位置 | 预期 |
|---|---|---|
| iTransformer | 编码器的自注意力 | 本地实验的主对照，已验证 |
| S-Mamba / GPS-Mamba | 变量维的 Mamba 扫描 | 同时去掉对扫描顺序的依赖（5.3 已表明顺序无益） |
| TQNet | 周期 query 注意力（周期向量保留在时间分支） | 与日历修正互补 |
| DyTimeNet | CrossVBlock（本身接近静态 MLP） | 改成“低秩 + 稀疏 + 日历修正”，验证增益 |
| MoVE | RCVTE 专家（RCVA 按公式推导本来就近似均匀混合） | 简化并提升 |
| CycleNet / PatchTST 等 CI 模型 | 作为额外的跨变量分支，零初始化 | 不伤害弱耦合数据 |

**在 GPU 上必须完成的验证**

1. 在官方框架（Time-Series-Library）上按官方超参复现，L ∈ {96, 336}，H ∈ {96, 192, 336, 720}，3 个种子；数据集包括 ETT×4、Weather、ECL、Traffic（完整数据）、Solar、PEMS03/04/07/08。
2. 对照基线：iTransformer、TQNet、CycleNet、PatchTST、S-Mamba、DyTimeNet、TimeXer；交通任务另加 STID、STAEformer。**所有基线都要带时间特征。**
3. 消融：静态 vs 注意力、日历修正、DropConnect、低秩 + 稀疏 vs 稠密、零初始化、分组粒度（4 小时段 / 1 小时段 / 加节假日）、混合版。
4. 效率：参数量、FLOPs、推理延迟、显存，重点测 Traffic（862 个变量）。

**可以继续做的子改进**

- **自动容量**：秩和稀疏度按“训练样本数 / 变量数”自适应，或用 L0 门自动学稀疏模式，解决 Traffic 这类数据少、变量多的情况。
- **动静结合**：只在动态依赖强的数据集（如 Solar）启用注意力分支，或用门控自动决定动态分支的权重。
- **多周期日历**：日、周、节假日一起建模；时段由数据聚类得到，不再手工切分。

**风险**

- TSMixer、SOFTS、STID 已经使用静态混合或时间嵌入，必须用消融证明三点设计（结构化 W、日历调制混合矩阵、即插即用）各自的增益。
- 完整数据、更长训练下，注意力可能缩小差距（ECL 数据增加后，注意力已从输给 CI 变成小胜 CI）。

### 改进 B ★★：粗到细预测的按样本自适应计算

**定位**：效率改进。给 SCALER 这类“先粗后细”的模型加一个学到的提前停止头，按样本决定细化几步。

**本地结果**：在误差不超过最佳固定 +1% 的前提下省 7–32% 的计算；在中等预算下，精度最多高 10%（5.4 节）。

**下一步（GPU）**

1. 在 SCALER 官方代码上接入停止头，报告精度–算力的 Pareto 曲线。
2. 同时做“LLM 换成随机初始化或小 Transformer”的对照：如果大 LLM 并非必要，就是“更省又不掉点”的双重改进。

### 改进 C ★：原生多变量时序基础模型的分组策略

**依据**：Chronos-2 的多变量模式零样本 +9–15%，外挂适配器无效（5.5 节）。

**改进思路**

- 不再把全部变量放进一组，而是按（去因子）相关聚类分组，或按语义分组，在显存 O(V) 的约束下提升精度。
- 变量很多时（Traffic），分组还能降低计算量。

**下一步**：在 GPU 上用 Chronos-2，在 PEMS08 / Traffic 上比较不同分组方式（约 1–2 天）。目前未验证，排在最后。

### 不推荐

| 方向 | 理由 |
|---|---|
| ③ Mamba 扫描顺序 | 效应 ≤3%，谱排序无益 |
| ⑥ LLM 语义先验图 | 对预测无收益 |
| 按相位或按样本“换图” | 不如静态图 |
| 用注意力实现的动态依赖模块 | 被 SCM 取代 |
| 诊断 / 分析类工作 | 按你的要求不做 |
| LLM 当数值预测骨干、单种子刷 SOTA、单纯换 Mamba、单纯 TTA | 同 v1 |

## 7. 推进路线（约 8–10 周，需要 GPU）

1. **第 1–2 周**：把 SCM 写成 Time-Series-Library 中的独立模块，接入 iTransformer、TQNet、S-Mamba。在完整数据、官方超参、3 个种子下跑长期预测基准，确认本地结论成立。
2. **第 3–4 周**：消融与效率。各组件、分组粒度、秩与稀疏度；在 Traffic 上测参数量、FLOPs、延迟和显存。针对 Traffic 做容量自适应，针对 Solar 做动静结合。
3. **第 5–6 周**：交通 / 时空短期预测（PEMS03/04/07/08，H=12），与 STID、STAEformer 等时空模型对比。日历修正在交通数据上的作用最强，这部分可以单独成为卖点。
4. **并行可选**：改进 B（SCALER + 自适应停止）、改进 C（Chronos-2 分组）。
5. **第 7 周起**：写作。方法型论文，可投 KDD、AAAI、IJCAI、CIKM，或 Neurocomputing、ESWA（与库内论文同档）。

## 8. 写论文时建议补齐的实验规范

- [ ] 至少 3 个随机种子，报均值和标准差；关键结论做显著性检验。
- [ ] 同时报告 L=96 和搜索后的最优 L；`drop_last=False`；基线**自己重跑**，不要直接抄数字。
- [ ] **所有基线都配上时间戳 / 日历信息。** 仅时间嵌入就能让交通数据误差降 36–40%，否则会高估跨变量模块的作用。
- [ ] 用同一骨干只换跨变量模块做主消融；“静态混合”和“CI + 时间”必须作为强基线出现。
- [ ] 报告训练窗口数与变量数之比；数据少、变量多时（Traffic）单独讨论。
- [ ] 效率指标报全：参数量、FLOPs、延迟、显存，至少在一个高维数据集（Traffic）上测。
- [ ] 按耦合强度分组报告：强耦合组（PEMS、SD、Solar、Traffic）和弱耦合组（ETT、ECL、Weather）。
