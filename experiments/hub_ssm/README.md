# Hub-SSM：与变量顺序无关的跨变量混合器（合成数据实验）

本目录记录了一组小规模实验，用来检验一个问题：**Mamba 类模型在变量维度上建模相关性时，能否既不依赖人为指定的变量顺序，又能区分不同变量对之间的关系？**

实验分两次进行：

- **第一次实验（轮次 1–3 及 v2）**：枢纽式低秩混合器 Hub-SSM。
- **第二次实验（轮次 4）**：在 Hub-SSM 基础上加入稀疏 top-k 项，即"低秩 + 稀疏"混合器。

> 这些都是合成数据上的 CPU 小实验（64 个变量、800 步训练、未调超参、每种配置 3 个种子），只能用来判断方向和排除坏设计，不能代替真实数据集上的结论。

## 结论速览

- **第一次实验（Hub-SSM）**：严格与变量顺序无关，复杂度对变量数线性，这两点都验证过。但精度只和简单的均值池化持平：在"固定簇 + 时滞"数据上只拿到全注意力约一半的收益，在簇结构随时间切换的数据上没有优势。
- **第二次实验（低秩 + 稀疏）**：稀疏 top-k 项带来大幅提升。在全部 4 种设置下比 CI 低 17–27%，比全注意力再低 11–14%（稀疏 k=16 对注意力的 12 组种子配对全部更好）；学到的候选近邻明显富集同簇变量。**低秩枢纽分支在稀疏项之上没有可靠的额外贡献**（相对纯稀疏 −1.4% ~ +1.3%，各种子正负不一），有效成分是"只看少数相关变量、按内容加权"。
- **新颖性提醒**：稀疏 top-k 变量依赖已有同期工作（MS-FLOW，2026 年 5 月，按每个样本的内容分数取 top-K）以及更早的图学习方法（MTGNN 的 top-k 邻接、AGCRN 的节点嵌入）。这里的价值是在可控数据上验证这个方向，而不是提出新方法。
- **真实数据上没有复现**：在 Electricity 上，稀疏变量混合比注意力和双向 Mamba 都差；在真实数据上稳定有效的改进是变量身份嵌入。详见 [`../real_data/README.md`](../real_data/README.md)。

## 1. 动机

S-Mamba（仓库中 #6）把每个变量的整段历史压成一个 token，再用双向 Mamba 沿变量维度扫描。但变量本身没有顺序。把 Mamba-2（SSD）写成作用在变量维度上的矩阵形式：

```
y_i = Σ_j M_ij · x_j ,    M_ij = (C_iᵀ B_j) · L_ij
L_ij = a_{j+1}·a_{j+2}···a_i   (j ≤ i)，否则为 0
```

顺序依赖全部来自 L：因果掩码加上按扫描距离衰减。GPS-Mamba（#10）观察到扫描距离远的变量权重偏低，就是 L 造成的。现有工作大多在"给变量找一个更好的顺序"（MambaTS、SOR-Mamba、CRS-Mamba、GPS-Mamba 的 Laplace 扫描）。VI 2D SSM 则直接去掉了顺序，但它证明了线性的置换等变耦合只能是 αI + β11ᵀ，即所有变量对一视同仁。

去掉 L 后 M = C·Bᵀ，对变量置换严格等变。如果 B、C 随输入变化（Mamba 的选择性），M(x) 就是随数据变化、秩不超过 K、不同变量对可以不同的矩阵，同时仍然等变。这是 Hub-SSM 的出发点。

## 2. 方法

所有模型共用同一个骨架（`models.py` 中的 `Forecaster`）：

```
实例归一化(RevIN) → 每个变量切成长度 8 的 patch 并嵌入（D=32）→ 加位置嵌入（+ 变量身份嵌入）
→ 变量混合器 → FFN → 线性输出头（拼接所有 patch 后一次输出 16 步）
```

不同模型只有"变量混合器"不同。

### 2.1 Hub-SSM v1（`HubSSMMixer`）

变量 j 在第 p 个 patch 的 token 记为 x_{j,p}，模型维护 K 个枢纽状态：

```
写入  w_{j,p,k} = B_{j,p,k} · Δ_{j,p,k}          B = softmax_K(W_B[x_{j,p}; e_j])
状态  H_{p,k} = exp(−Δ̄_{p,k}·A_k) · H_{p−1,k} + Σ_j w_{j,p,k} · v_{j,p}
      m_{p,k} = exp(−Δ̄_{p,k}·A_k) · m_{p−1,k} + Σ_j w_{j,p,k}
读出  y_{i,p} = Σ_k C_{i,p,k} · H_{p,k} / m_{p,k}    C = softmax_K(W_C[x_{i,p}; e_i])
输出  x_{i,p} + W_o( y_{i,p} ⊙ SiLU(W_z x_{i,p}) )
```

- B 是软聚类，枢纽 H/m 是成员随时间衰减的加权质心。
- Δ̄ 是写入步长按 B 加权的平均，与变量顺序无关。
- 每个枢纽有自己的衰减率 A_k，相当于多时间尺度。
- 沿 patch 的递推让变量 j 过去的信息能影响变量 i 现在的输出（跨变量滞后）。
- e_j 是可学习的变量身份嵌入。"与顺序无关"不等于"不认识变量"。

### 2.2 Hub-SSM v2（`HubSSMMixer(select=True)`）

写入权重改为 exp(s_{j,p,k})，在变量维度上归一化（每个枢纽自己挑选变量），写入前再乘按变量的缩放 γ(e_j)，用来对齐正负号和量纲。

### 2.3 稀疏 top-k 项（`SparseTopKMixer`）

```
候选  N(i) = 在节点嵌入空间中与 e_i 余弦相似度最高的 k 个变量（不含自身）
权重  α_{ij,p} = softmax_{j∈N(i)}( q_{i,p}·k_{j,p}/√D + λ·cos(e_i, e_j) )
输出  x_{i,p} + W_o Σ_{j∈N(i)} α_{ij,p} · v_{j,p}
```

- 候选集每次前向只算一次，代价 O(N²·d_e)，与 batch 和 patch 数无关，推理时可以缓存。
- 权重随内容变化，所以同一组候选在不同时段可以有不同的组合。
- 训练时每个变量额外随机加入 k/2 个候选，让暂时不在候选集里的有用变量也能拿到梯度、进入 top-k；评估时只用 top-k。
- 嵌入与数据一起置换时输出随之置换，同样与顺序无关。

### 2.4 低秩 + 稀疏（`LowRankSparseMixer`）

M ≈ C·Bᵀ + S：Hub-SSM v2 负责全局、低秩部分，稀疏项负责精确的变量对路由，两个分支的残差相加。

### 2.5 基线

| 名称 | 说明 |
|---|---|
| CI (no mixing) | 不做跨变量混合，每个变量只看自己的历史 |
| MeanPool (homogeneous) | DeepSets 式：非线性编码后对所有变量取平均，所有变量读同一个全局量（VI 2D SSM 类型的同质耦合） |
| Attention O(N²) | 每个 patch 上对全部变量做 4 头 softmax 注意力（iTransformer 式） |
| Bi-scan S6 (S-Mamba-like) | 沿变量维度的前向 + 反向选择性扫描（无卷积的 Mamba S6），依赖变量顺序；纯 Python 循环，在 CPU 上很慢，只在轮次 1 中运行 |

## 3. 合成数据与训练设置（`data.py`、`train.py`）

- 64 个变量，分 4 个簇，每簇 16 个。每簇有一个潜在驱动序列：AR(1)（φ=0.97），`season=1` 时再加一个周期在 [20, 40) 的正弦。
- 每个变量以 0–12 步的时滞复制所在簇的驱动序列，随机正负号（70% 为正）、随机尺度 [0.5, 1.5]，加 N(0, 0.3²) 噪声。跟随变量未来若干步可以从领头变量的过去看到。
- **static（静态）**：簇固定，每簇第一个成员是时滞为 0 的领头变量，变量顺序随机打乱。
- **dynamic（动态）**：两种状态以 100–300 步为一段交替出现，每个变量在两种状态下属于不同的簇。
- 序列长 12000：前 8000 步训练，之后为测试；回看 48 步，预测 16 步；按训练段统计量标准化。
- 训练：AdamW，学习率 2e-3，余弦退火，batch 64，800 步；种子 0/1/2。
- 指标：标准化后的测试 MSE。"相对 CI"是同一种子下与 CI 配对比较后再平均。

## 4. 性质检查（`check_props.py`，结果见 `logs/check_props.log`）

| 检查项 | 结果 |
|---|---|
| 置换等变（数据与节点嵌入一起置换） | Hub 2.4e-7、Hub-v2 2.4e-7、稀疏 0、低秩 + 稀疏 4.8e-7；双向扫描 1.4e-2（依赖顺序） |
| 时间因果（扰动第 4 个 patch） | 第 0–3 个 patch 的输出变化均为 0 |
| 跨变量滞后（扰动变量 7 的第 1 个 patch） | 变量 3 在第 1–5 个 patch 上受到 2.7e-3 → 1.6e-4 的逐步衰减影响 |
| 耦合结构（Hub） | 数值秩 = K = 8，变量对之间的权重不同（变异系数 0.19）；均值池化为秩 1、所有变量对相同 |

前向耗时（CPU，单位 ms，batch 4，12 个 patch，D=64，K=16，k=8）：

| N | Hub-v2 | 低秩 + 稀疏 | 全注意力 |
|---|---|---|---|
| 256 | 13 | 35 | 20 |
| 1024 | 53 | 149 | 252 |
| 4096 | 215 | 1299 | 5729 |
| 8192 | 487 | 2031 | 内存溢出 |

Hub-v2 随 N 线性增长。低秩 + 稀疏多了一次 O(N²·d_e) 的候选检索（每次前向只做一次、与 batch 和 patch 无关，推理时可缓存），所以 N 很大时略超线性，但在 N=4096 时仍比全注意力快约 4.4 倍。GPU 上用 FlashAttention 时差距会缩小。

**第一次实验的结论：**

1. Hub 与均值池化分不开。均值池化先过非线性编码、再有身份嵌入，就能把不同簇编码进不同子空间，等效于多个枢纽，所以"异质性优势"实际很难拉开。
2. 固定簇 + 时滞的场景下，全注意力明显更强（无周期项时 −17.7%，Hub 系列最好只有 −10.5%）。枢纽是成员的平均，正负号、时滞不同的成员互相抵消，无法像注意力那样直接指向领头变量；v2 让枢纽自己挑选变量，只把差距缩小了约四分之一。
3. 簇结构随时段切换的场景下，所有方法（包括注意力）都只比 CI 好约 4%，没有证据表明 Hub 能建模动态相关。

**第二次实验的结论：**

1. **稀疏项是有效成分。** 稀疏 k=16 相对全注意力：静态无周期 −11.4%，动态无周期 −13.2%，静态含周期 −11.2%，动态含周期 −14.0%，12 组种子配对全部更好。即使在簇结构随时段切换的数据上（所有稠密方法都只比 CI 好约 4%），稀疏项也能比 CI 好 17%。
2. **低秩枢纽分支没有可靠增益。** 低秩 + 稀疏相对同 k 的纯稀疏：k=8 时 −2.3%、+0.8%、−0.7%、+0.8%；k=16 时 −1.4%、+0.1%、−1.1%、+1.3%，各种子正负不一，落在种子噪声范围内。
3. **候选数要覆盖所有可能相关的变量。** 动态设置下 k=16 明显好于 k=8（−17.0% 对 −12.9%，−17.5% 对 −14.2%）：每个变量在两种状态下共有约 30 个同簇变量，k=8 装不下。权重随内容变化，所以同一组候选能在不同时段选出不同的组合。
4. **学到的近邻部分恢复了真实结构。** 近邻同簇比例在静态设置下为 0.51–0.77（随机 0.24），动态设置下为 0.62–0.78（随机 0.41）；跟随变量的候选中包含本簇领头变量的比例为 0.33–0.62（随机 0.13–0.25）。但种子间差异大，例如含周期的静态设置中，稀疏 k=8 有两个种子的领头命中率停在随机水平 0.13。
5. **为什么稀疏优于全注意力（假设，尚未分离验证）：** 一是只看少数候选，减少了无关变量带来的噪声，这与 DyTimeNet、CACRN 以及 MS-FLOW 噪声注入实验的结论一致；二是嵌入相似度项提供了一个容易学的、基于身份的路由先验。要分开这两个因素，需要"全注意力 + 嵌入相似度偏置"的对照，见第 7 节。

## 7. 总体结论与局限

- "与顺序无关"可以低成本地做到（已验证），但**"与顺序无关的低秩枢纽"本身不是有效的变量混合器**。真正起作用的是"从少数相关变量中按内容加权选取"。
- 低秩枢纽分支在加上稀疏项后没有额外贡献，因此不建议把它作为主创新；稀疏变量依赖本身已有 MS-FLOW 等同期工作，创新空间需要从别处找（例如候选检索的效率、与 Mamba 的结合方式、动态候选集）。
- **局限**：
  - 合成数据，只有 64 个变量；
  - 模型小（D=32），只训练 800 步，没有调超参；
  - 全注意力用 4 头，没调参；
  - 双向扫描只在轮次 1 中运行，且当时没有身份嵌入；
  - 每种配置只有 3 个种子。
- **下一步**：在真实数据集上，把稀疏项接到 iTransformer 和 S-Mamba 的骨架里，与原版的注意力和双向 Mamba 比较，并加入"全注意力 + 身份嵌入"等对照，以分离第 5 点的两个因素。结果见 [`../real_data/README.md`](../real_data/README.md)。

## 8. 复现

需要 Python 3 和 PyTorch（CPU 即可）。在本目录下运行：

```bash
python check_props.py                                   # 性质检查
# 轮次 2：含周期项；轮次 3：无周期项（--season 0）
python train.py --setting static  --season 1 --models ci,meanpool,hub4,hub8,attn --seeds 0 1 2
python train.py --setting dynamic --season 0 --models ci,meanpool,hub4,hub8,attn --seeds 0 1 2
# v2 与轮次 4
python train.py --setting static  --season 0 --models hubv2_8,hubv2_16 --seeds 0 1 2
python train.py --setting static  --season 0 --models sparse8,sparse16,lrs8_8,lrs8_16 --seeds 0 1 2
# 轮次 1（不加身份嵌入、单种子、含周期项、静态）
python train.py --setting static --season 1 --id 0 --models ci,meanpool,hub1,hub4_nomem,hub4,hub8,hub8_noemb,attn,biscan --seeds 0 --threads 4
python summarize.py                                     # 从 logs/ 生成上面的结果表
```

| 文件 | 内容 |
|---|---|
| `models.py` | Hub-SSM v1/v2、稀疏 top-k、低秩 + 稀疏混合器，以及各基线和预测骨架 |
| `data.py` | 合成数据生成（静态 / 动态，可开关周期项） |
| `train.py` | 训练与评估；`MODELS` 中列出全部模型的键名 |
| `check_props.py` | 等变性、因果性、滞后影响、耦合秩、规模计时 |
| `summarize.py` | 汇总 `logs/` 生成结果表 |
| `logs/` | 各轮原始日志：`round1`、`r2_*`（含周期）、`r3_*`（无周期）、`v2_*`、`r4_*`（低秩 + 稀疏）、`r4b_*`（稀疏 k=16 消融）。轮次 2 中双向扫描基线因 CPU 太慢被中止，没有结果 |
